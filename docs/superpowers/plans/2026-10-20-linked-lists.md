# 单链表实现计划

**目标：** 识别用户提供文件中的单链表节点格式，以红色节点和单向箭头演示实际的创建、链接、插入、删除和遍历。

**规则：** 完整结构体恰有两个成员：一个数值标量数据成员（可通过 typedef 命名），一个指向该结构体自身的单级指针。标记、别名、成员名、变量名均可修改；忽略空格和注释。其他可执行结构体保持普通结构体展示。识别基于规范化类型，不依赖函数名。标准模板保留用户示例的 typedef struct 写法。

**行为：** 链表节点采用红色框与有向边，节点按对象 identity 保持稳定；NULL、未初始化连接、断开的临时节点、共享指针、成环状态明确显示。新节点出现、指针改接、节点移动和删除逐帧平滑过渡；遵守现有暂停/停止/单步控制与滚动规则。删除先重接，再 delete，准确反映每条语句的中间状态。解引用释放的节点报告错误。

**兼容范围：** 为运行示例的 InitList，支持完整结构体的 `new Type`、`new Type()`、`delete p` 以及函数参数中的 `Type &name`（包括指针别名的引用）。这是教学解释器内部的对象管理，不执行用户本机 C/C++。暂不扩展 malloc、new[]、delete[]、类、递归与完整 C++。源代码定位保留原始行列。

**接口：**
- `Program.linked_types`: canonical structure type → `{'data': field_name, 'next': field_name}`。
- 普通 snapshot 保留原格式；每个识别出的 StructValue 根条目添加 `linked_node`，值为上述成员映射；根及成员有稳定 identity。所有存活堆对象加入 snapshot；释放对象移除，现有指针保留原 identity 以提示悬空。
- UI 从快照中的节点 identity 和 next 成员的 Pointer 得到实际边。独立 linked-list 模块负责布局、节点/箭头绘制和插值，接入 MemoryView/MotionLayer 现有进度，不增加独立动画计时器。

## 2026-10-21 用户追加要求

- 节点采用接近数组单元的小框，逐行从左到右排列，行间箭头走外侧空白通道，箭头不能被节点框遮挡；堆标识仅在悬停提示出现。
- 用户确认：每种节点类型最先声明的链表指针为头指针，其指向改变时头节点同步更新。
- 节点只有能从头节点到达，且沿后继能到达 NULL，才属于完整链表；完整链中的节点按照实际指针顺序排布，插入后平滑移入对应位置。
- 其他节点为滞空状态。后续仍可能使用的节点保留；确定不再使用的滞空节点在下一可观察语句淡出，仅隐藏展示，不执行 delete。
- 后续使用分析必须覆盖循环、分支、自定义函数参数和全局变量；不能仅按源代码行号或函数名称猜测。不能提前执行用户代码或请求输入来预测。
- 修复审查发现的短链表滚动空白（裁剪与重绘策略不一致）以及指针返回函数的引用参数解析问题，增加回归验证。
